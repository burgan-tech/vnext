## 1. What changed, in one table

| Topic | Before (≤ 0.0.98) | Now |
|---|---|---|
| `x-encryption.type` | `persisted`, `transport` in the vocabulary; not enforced by any runtime | `none`, `hash`, `encrypt`. `persisted` / `transport` are **rejected at publish** |
| `x-masking` | not a keyword | new: `mask` or `replace`, optional allow-only `roles` |
| `roles` on `x-masking` / `x-encryption` | — | **allow-only exemption list**: the listed roles see the raw value, everyone else the transformed one. `deny` is rejected at publish |
| Instance GET, instance list | served instance data **unfiltered** | apply `x-roles`, `x-masking` and `x-encryption`, like the data function |
| Sync start/transition response | `x-roles` only | all three keywords |
| `GetInstance` / `GetInstances` / `GetInstanceData` tasks | read as the system (`SystemRead`), unfiltered | evaluated **as the credential the task presents** (see §6); `SystemRead` is removed |
| Instance data in scripts | plaintext | an `encrypt` field is its **token**; `await context.Instance.DecryptAsync(path, ct)` opens the instance's own value |
| Credential on outbound tasks | `sub` / `act_sub` only, and only on some task types | `sub`, `act_sub`, `position`, `client_id`, `role` on **every** task type, wherever the mapping leaves them absent or empty |

Two of these are **behaviour changes for existing clients** and need a release-note line:
- GET and list now hide and mask fields that they used to return in full.
- A Get* task without headers now reads with its caller's visibility, not the system's.

## 2. Keyword contract

### 2.1 `x-masking`

```json
"iban": {
  "type": "string",
  "x-masking": {
    "operator": "mask",
    "params": { "keepFirst": 2, "keepLast": 4, "maskingChar": "*" },
    "roles": [ { "role": "morph-idm.auditor", "grant": "allow" } ]
  }
}
```

| Field | Values | Notes |
|---|---|---|
| `operator` | `mask` \| `replace` | required |
| `params` for `mask` | `keepFirst`, `keepLast` (non-negative integers, default 0), `maskingChar` (one character, default `*`) | the output keeps the input length; if `keepFirst + keepLast` ≥ length, the value is unchanged |
| `params` for `replace` | `value` (required string) | use when the length itself is sensitive |
| `roles` | allow grants only | omitted ⇒ masked for everyone |

### 2.2 `x-encryption`

```json
"tckn":  { "type": "string", "x-encryption": { "type": "hash", "params": { "algorithm": "sha256" }, "purpose": "PII-Identification" } },
"email": { "type": "string", "x-encryption": { "type": "encrypt", "roles": [ { "role": "morph-idm.auditor", "grant": "allow" } ], "purpose": "PII" } }
```

| Field | `none` | `hash` | `encrypt` |
|---|---|---|---|
| Effect | metadata only | applied **on write**: stored and served as `HASHED:SHA256:<hex>` (HMAC with a per-instance salt) | stored as `ENCRYPTED:AES256:i1:…` (AES-256-GCM, per-instance key); opened on read for allow-listed callers |
| `params` | not allowed | `algorithm`: `sha256` (default) \| `sha512` | not allowed |
| `roles` | — | **not allowed** (the raw value no longer exists) | allow-only exemption list |
| `purpose`, `redactInLogs`, `retentionDays` | governance metadata, not enforced | same | same |

Keys and salts are generated by the runtime per instance. They never appear in a schema, in configuration, or on any
API.

### 2.3 Allow-only exemption semantics (both keywords)

| Caller | Sees |
|---|---|
| holds a listed role (alone or with others) | raw value |
| holds only unlisted roles | transformed |
| misspelled role, no roles, or role resolution failed | transformed (fail closed) |
| no `roles` declared | transformed for everyone |

Predefined and dynamic grants (`$InstanceStarter`, `$user.$.context.…`) are valid list entries. A caller without
roles can never satisfy a role-bound grant.

## 3. Publish-time rules — what the designer should catch first

Forge should flag these before publish. The runtime rejects every one of them (`FieldMaskingDefinition`):

| Rule | Runtime message (abridged) |
|---|---|
| The keyword sits under nested `properties` only (not under `items`, `$defs`, combinators or conditionals) | not reachable through nested `properties` |
| The property declares `type: "string"` (optionally `["string","null"]`) | must be a string property |
| `x-masking` together with an active `x-encryption` (type other than `none`) | "declare one transform per field" |
| `x-masking` keys other than `operator`, `params`, `roles` | "Allowed: operator, params, roles" |
| `operator` other than `mask` / `replace`; parameters of the other operator; `replace` without `params.value` | per-key messages |
| `maskingChar` longer than one character; negative `keepFirst` / `keepLast` | per-key messages |
| `x-encryption.type` missing, not lower case, or `persisted` / `transport` | "has been removed; use 'encrypt'" |
| `params` on `none` or `encrypt`; `params` keys other than `algorithm` on `hash` (no salt or key) | per-key messages |
| `roles` on `hash` | "the raw value no longer exists" |
| a `deny` grant, or a malformed dynamic grant, in any exemption list | allow-only |
| `hash` with `pattern`, `format`, `minLength`, `maxLength`, `enum` or `const` | the digest would fail validation on the next write |
| any of the three with `x-filterOperators`, `x-sortable` or `x-indexed` | protected fields cannot be queried |
| `hash` / `encrypt` on a host with `SchemaEncryption:EncryptWrites=false` | rejected by `SchemaComponentValidator` |

Also tell authors:
- **Bump the schema version** when changing these keywords. Re-publishing the same version does not move the
  data-function ETag.
- A field used as a **role** (dynamic grants) or a **human-task title / description** should not be `encrypt`. Those
  surfaces see the token.

## 4. Read surfaces

| Surface | `x-roles` | `x-masking` | `encrypt` | `hash` |
|---|---|---|---|---|
| Instance GET, instance list, data function, sync start/transition response | pruned | allow-listed → raw, others masked | allow-listed → plaintext, others the stored token | stored digest |
| `GetInstance`, `GetInstances`, `GetInstanceData` tasks (same domain and cross-domain) | same, for the task's credential | same | same | same |
| Scripts (`context.Instance.Data`, runtime-filled `context.Body`) | not applied | not applied | **token**; `DecryptAsync` opens it | digest |
| Not covered (row as stored): transition history, `context.Related`, custom functions, human-task list, events, internal endpoints | — | — | token | digest |

Filter, sort, groupBy and aggregation on an `encrypt` path (or its parent object) are refused with 400
`Validation:900010`.

## 5. Scripts — token and `DecryptAsync`

```csharp
var raw  = context.Instance.Data.vault.email;                                   // "ENCRYPTED:AES256:i1:…"
var mail = await context.Instance.DecryptAsync("vault.email", cancellationToken); // "user@example.com"
```

| Member | Contract |
|---|---|
| `Task<string?> Instance.DecryptAsync(string path, CancellationToken cancellationToken = default)` | Takes a **path** of the instance's **own** latest data, never a value. Returns the plaintext, or `null` for: a plain field, an unknown path, a value that cannot be opened, a token string passed as a path, or a host without the keyring. A cancelled token throws `OperationCanceledException`. |
| `context.Instance.Data`, `LatestData.Data`, `FindData(v).Data` | the row as stored (tokens included) |
| `context.Body` of a SubFlow output mapping in the parent | the child's data **in clear**; the child opened it with its own key |
| DynamicExpresso rules, function-cache `varyBy` | token; there is no `await`, so use a C# condition script |

Writing back:
- the same token at the same path is a no-op;
- a plaintext value is encrypted again;
- a token written to any **other** field is refused (`EncryptedValueReservedException`).

Copying a decrypted value into another field removes its protection; that is the author's decision.

## 6. Task credential forwarding

One rule for HTTP, SOAP, DaprService, DaprHttpEndpoint, GetInstance, GetInstances, GetInstanceData, Start, SubProcess
and DirectTrigger tasks:

> For each of `sub`, `act_sub`, `position`, `client_id`, `role`: when the task's header mapping leaves it absent **or
> empty**, the value from the incoming **request** headers is sent. A non-empty mapping value always wins.

- `role` travels only as the caller sent it. Roles that a provider resolved for the caller (morph-idm get-roles) are
  never forwarded; the target resolves them from the forwarded credential.
- A Get* task with no headers therefore reads **as its caller**. To read as a service identity, set the credential (or
  just `role`) in the input mapping.
- Values are validated (no control characters, ≤ 1024 characters); an unsafe value is not forwarded.

## 7. Error codes authors and clients see

| Code | HTTP | When |
|---|---|---|
| `Instance:100041` | 400 | a request introduces a value starting with `ENCRYPTED:AES256:` (anywhere) or `HASHED:` (on a hash path) that is not the value already stored there. Checked before admission, so the instance is not faulted |
| `Instance:100043` | 503 | the schema cannot be resolved while the instance already carries protected values; the write is refused rather than stored in plaintext |
| `Instance:100040` | 503 | a write would carry forward a value whose secret is gone (secret row deleted outside the runtime, or token tampered). Reads never fail on such a value; they serve the token |
| `Validation:900010` | 400 | a list query filters, sorts or groups on an `encrypt` path |

## 11. Known gaps (do not document as guarantees)

- **Scope is instance data only.** These still hold plaintext: transition request bodies and headers, task journals,
  outbox payloads, job payloads, the human-task cache, and history rows written before a field became protected.
- **Event selectors** (`FindByFilterAsync`) carry no schema context and are not guarded.
- **Crypto-shredding.** Deleting an instance's `InstanceSecrets` row makes its encrypted values unrecoverable; a pod
  stops opening them only once its in-process cache entry expires (sliding, default 30 min) or the pod restarts.
