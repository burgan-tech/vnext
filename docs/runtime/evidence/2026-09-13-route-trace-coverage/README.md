# Live evidence — route trace coverage

Measured 2026-09-13 against the local stack (`etc/docker/run-docker.sh up core`), hosts built from
`feature/full-route-trace-coverage`, traffic generated by the vnext-example integration suite.

**Read in Elasticsearch, not OpenObserve.** Elastic resolves nesting strictly through `parent.id` and
re-parents an orphan to the trace root, so it is the renderer that can disprove a parentage claim;
OpenObserve groups by trace id and is far more forgiving. The 2026-08-30 verification recorded in
[trace-span-tree.md](../../trace-span-tree.md) was measured in OpenObserve, which is why its numbers
are annotated there as not-a-baseline.

Index pattern: `.ds-traces-apm*,traces-apm*`.

## 1. The new spans are exported

Aggregation over `span.name` for the last 30 minutes of test traffic:

| Span | Count |
|---|---:|
| `Event.Intake` | 9 |
| `Instance.Read/list` | 8 |
| `Instance.Read/state` | 6 |
| `Instance.Read/instance` | 4 |
| `Auth.FilterTransitions` | 3 |
| `Inbox.Forward` | 3 |
| `Instance.Read/incidentActive` | 1 |

Exported means the source reached the tracer provider in that host — the failure this cannot have is
the silent one, where an unregistered source makes `StartActivity` return null and the span is never
created at all.

## 2. The hot path costs zero span documents

The load-bearing claim of the whole catalogue, in production-shaped data rather than a unit test.
Aggregation over `labels.vnext_read_fastpath`, same window:

| Outcome | Documents | Document type | `Instance.Read/state` spans |
|---|---:|---|---:|
| `cacheHit` | 233 | transaction | 0 |
| `build` | 6 | transaction | 6 |

**233 fast-path state reads produced no span at all**, while 6 builds produced exactly 6 envelopes.
The discriminator still travelled on every one of the 239: `vnext.function.key=state` plus the
outcome, on the transaction, at zero added documents.

That is the council's G-1 condition satisfied as a measurement. It matters because no sampler is
configured in any host, so every recorded span is exported — with untuned OpenTelemetry defaults a
burst on this route would overflow the queue and drop spans indiscriminately, including the pipeline
spans the trace tree exists to protect.

## 3. One event-driven trace, end to end

Trace `db6e350c4f3759fb4545085c8818ae17` — a message published to a topic, delivered by a Dapr
subscription, mapped and applied to a running instance. Nothing in this path was reachable from a
trace before: the `instances/events` endpoint had no coverage of any kind.

```
TXN /v1.0/publish/vnext-pubsub/core.event-driven-lab.approve
  pubsub/core.event-driven-lab.approve                          2 997 us
TXN POST .../workflows/{workflow}/instances/events
  Event.Intake                                                  1 513 us
    Cache.Get/sys-flows:core:event-driven-lab:…                    79 us
    ScriptContext.Build / MergeBody                             10 / 4 us
    Script.Compile/./src/ApproveEventMapping.csx                   14 us
    Instance.Query.Prepare                                        234 us
    Instance.Query.Execute                                        865 us
      Db.SELECT                                                   729 us
```

The intake half is what had never been named: definition resolve, CloudEvent unwrap, the mapping
script and the correlation lookup all ran as one anonymous region under the endpoint's server span.
The breakdown above is the answer to "why did this event take a second", which previously had none.

## 4. How to reproduce

```bash
cd etc/docker && ./run-docker.sh up core --offset 0
cd ../../../vnext-example && wf domain use core && wf sync
docker restart vnext-orchestration-dapr          # Dapr reads declarative subscriptions at startup only
VNEXT_BASE_URL=http://localhost:4201 VNEXT_DAPR_HTTP_URL=http://localhost:42110 \
  dotnet test tests/Core.IntegrationTests --filter "FullyQualifiedName~EventDrivenLab"
```

Kibana renders the same data at `:5601` (Observability → APM → Traces). It is **not** started by
`run-docker.sh`; bring it up with `docker compose up -d kibana` from `etc/docker`.

## 5. What this does not cover

- **Cross-domain.** `Remote.Send` and the descent ladder are not exercised here; that needs the
  vnext-example cross-domain lab, whose collector currently exports to OpenObserve only.
- **`Instance.Read/data`, `/view`, `/schema`, `/master`, `/extensions`, `/history`, `/hierarchy`,
  `/humanTasks`** — implemented and unit-guarded, but the traffic in this window did not reach them.
  Absence here is absence of traffic, not absence of the span.
- **`Auth.Decide`, `Auth.PreviousUserLookup`, `View.Resolve`, `Schema.Validate`, `Remote.Send`,
  `SubFlow.ChildFault`, the function response cache** — same: no traffic in this window.
- **`Instance.Read.BuildGate`** is the one catalogue item not implemented at all.
